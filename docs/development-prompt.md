# 提示词：新员工入职工具箱（v4）

> 本提示词由一次完整的多轮迭代开发沉淀而成，可直接交给模型执行。
> 功能需求、NAS 环境约束与工程要求均为经过验证的"正确形式"；
> 前端界面给出设计目标、交互规格与硬性经验，视觉实现细节交由模型自由发挥。

## 背景

为 corp1.local / corp2.local 双域环境开发一个新员工入职支持工具，供 IT 在新员工入职时使用。两个域中相同员工号的账号使用相同的初始密码。

### 员工号格式

字母前缀 + 数字，长度不固定（如 `J10065`、`J10202`），直接使用原始字符串作为输入。
正则校验：`^[A-Za-z]+[0-9]+$`。

### 域与 NAS 对应关系

| 域 | NAS IP | 账号格式 |
|---|---|---|
| corp1.local | 192.168.100.10 | `CORP1\员工号` |
| corp2.local | 192.168.200.22 | `corp2\员工号` |

## 密码生成算法（全工具唯一实现，逐字符强约束）

### 内置 Seed（逐字符固定，禁止改动）

```
REPLACE-WITH-YOUR-OWN-SECRET-SEED
```

**任何重写、任何语言实现都必须使用这个逐字符相同的 Seed**——改动一个字符，
所有存量员工的初始密码就会与已建账号全部对不上。
Seed 直接内置源码，不依赖外部文件，不出现在界面/日志/控制台。

### 算法步骤

1. 拼接字符串：`员工号_2026`（示例：`J10065_2026`）
2. `HMAC-SHA256(Seed, 拼接字符串)` → Base64 编码 → 取前 8 位
3. 复杂度修复：8 位必须含大写/小写/数字/特殊符号四类。基于原始 8 位判断
   缺失类别，按固定位置确定性替换，替换字符取自 HMAC 摘要字节：
   - 缺大写 → 第 3 位 = `'A' + digest[8] % 26`
   - 缺数字 → 第 5 位 = `'0' + digest[9] % 10`
   - 缺符号 → 第 7 位 = `"!@#$%^&*"[digest[10] % 8]`
   - 缺小写 → 第 1 位 = `'a' + digest[11] % 26`
4. 算法单独成文件（`PasswordGenerator.cs`），全项目只维护这一份实现。

## NAS 环境约束（强约束，来自现场实测）

目标 NAS 是 **Samba 设备**，以下两条都是踩坑换来的硬约束：

1. **不暴露可用的 IPC$**：`net use \\IP\IPC$` 恒返回系统错误 67
  （找不到网络名），凭据正确也必败。**绝不能用连接 IPC$ 的方式做探测。**
2. **net view 不可靠**：部分客户端上 net view 对任意地址报 1702
  （绑定句柄无效）；其文本输出解析对含空格的共享名、非 Windows 输出
   格式都容易漏抓。**枚举共享必须用 netapi32 的官方 API `NetShareEnum`**
   （net view 的内部实现同款，但返回结构体数组，天然支持含空格共享名）。

### 探测与凭据写入分离（核心设计，顺序固定）

**原则：探测阶段绝不写凭据管理器；凭据只在用户确认"映射"时才写入。**

探测流程（三级策略）：

1. 优先用本机已有会话/凭据直接 `NetShareEnum` 枚举（已有访问权限时零副作用；
   日志注明"使用本机已有凭据"）。注意：SMB 会话会复用，此时共享列表是
   已有凭据的视图，输入的凭据在映射时才真正验证——这是有意的取舍
2. 失败则用输入凭据建立临时会话（`net use \\IP\IPC$ /user:... ...`，不落盘），
   枚举后拆除
3. NAS 拒绝显式 IPC$（Samba 常见，错误 67）时回退为 cmdkey 保存凭据后枚举
   （此时无旧凭据可覆盖；枚举失败则回滚删除刚存的凭据）

映射流程：

1. 用户点击"映射选中共享"→ 按服务器写入凭据（`cmdkey`，两个域账号不同：
   `CORP1\员工号` / `corp2\员工号`）→ `net use \\IP /delete /y` 清旧会话让新凭据生效
2. 逐个映射；某服务器映射**全部失败**时回滚刚保存的凭据并提示检查用户名密码
3. 汇报成功/失败数

注意：`cmdkey` 读不出已存密码，覆盖即丢失——这正是"探测不写凭据"的原因。
枚举后过滤共享：空、`IPC$`、`$` 结尾的隐藏共享。
错误诊断写进日志：5=拒绝访问（凭据错误）、53=服务器不可达、1219=凭据冲突、
其他=错误码原文。

## 产品形态

单个 Windows 桌面应用（exe，双击即用），含三个功能页（Tab）。
技术约束见"工程要求"。程序集信息（Windows 文件属性可见）：

### 功能页一：NAS懒人映射

供 Helpdesk 在新员工电脑上运行（电脑不加域）：

1. 输入员工号（校验：空 → 提示；非"字母+数字" → 提示格式不正确）
2. 自动计算初始密码（**界面不显示**）
3. 按上述探测流程依次探测两个内置 NAS
   - 成功：凭据已保存到 Windows 凭据管理器，列出该 NAS 全部共享
   - 失败：日志写明真实原因，继续另一个
   - 两个均失败 → 提示"该员工无任何 NAS 访问权限"
4. **忽略NAS预设共享**开关（默认开启）：过滤 `homes / docker / music / video`
   （大小写不敏感）；切换后按原始探测结果即时重新过滤，无需重新探测
5. 合并显示共享列表（标注来源 NAS），交互规格：
   - 每项显示**即将映射的盘符徽章**（Z:、Y:、X: …… 只分配给勾选项，
     取消勾选后自动重新分配）
   - 单击勾选；**按住拖动排序**：被拖项悬浮（投影 + 强调条），
     其它行动画退避让位，松手平滑归位
   - 列表为空时显示引导文案
6. **窗口随共享数量自动加长**：列表默认约 4 行高，最多加长到容纳 10 行
   （下方按钮与日志区整体下移，窗体同步加高）；超出 10 行走列表内滚动
7. 映射：按列表顺序从 `Z:` 依次向下分配盘符（最低 `D:`，自动跳过已占用），
   `net use X: \\IP\Share /persistent:yes`，使用已保存凭据
8. 汇报：成功数 / 失败数 / 跳过的 NAS
9. 附 **一键清除所有映射**：枚举当前用户全部网络驱动器（WMI
   `Win32_MappedLogicalDisk`）逐一断开，操作前弹确认框

### 功能页二：初始密码查询

供 IT 新建 AD 账户时使用：输入员工号 → 生成密码 → 一键复制到剪贴板。
密码仅显示在界面，不自动保存到任何文件。
生成时播放 **1 秒乱码解码动画**（字符从字符池随机滚动、从左到右依次定格、
底部强调线同步扫过），动画完成后才启用复制按钮。

### 功能页三：自定义映射

手动输入 **服务器地址（IP 或主机名）+ 用户名 + 密码**（不要要求完整共享路径），随后流程与功能页一完全一致（同一套探测/映射代码，含预设共享开关与窗口自适应）。同样附一键清除所有映射。

### 界面文案约束

- 全部中文提示，错误提示清晰具体（附真实错误原因）
- 界面中不出现 "(CORP1 / corp2 双域)" 字样，不出现员工号示例（如 "（如 J10065）"）

### 安全要求

- Seed 内置于源码，不出现在界面、控制台、日志或任何文件
- 密码仅用于临时探测与凭据保存，不在控制台/界面输出（密码查询页除外），使用后主动清除内存变量
- 探测失败的凭据必须回滚删除，不留错误凭据
- 映射类操作基于 net use / cmdkey / netapi32 / WMI，无需管理员权限

## 界面设计（定目标与硬性经验，视觉实现自由发挥）

- **风格**：现代桌面软件审美，Win11 原生设计；系统默认标题栏/边框与界面风格禁止割裂，需自绘窗口装饰
- **字体固定为微软雅黑**（标题 13 Bold / 正文 9.5 / 辅助 8.5 / 日志 9 / 密码展示 20 Bold）
- **窗口装饰用 DWM 官方 API**：
  `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE=33, DWMWCP_ROUND)` 原生圆角 +
  `DwmExtendFrameIntoClientArea(1px)` 官方阴影边框。
  **禁止 `Region` 裁剪圆角**（GDI Region 是像素蒙版，完全不抗锯齿，必有锯齿）；
  控件圆角一律用"父容器同色填充 + 抗锯齿绘制"实现
- **DPI 感知**：`SetProcessDPIAware` + `AutoScaleMode.None`，
  高缩放显示器原生清晰渲染
- **布局**：一致的间距比例（建议 8px 网格），各功能页保持统一的视觉节奏
  （标题 → 表单 → 列表 → 操作 → 日志），窗口不拥挤、留白充分；
  表单输入框按标签实测宽度对齐，标签垂直居中于输入框（不要按坐标目测对齐）
- **主题**：颜色、圆角、阴影等抽取为统一的设计变量（design tokens），一处修改全局生效；
  阴影带蓝灰色调（不用纯黑）
- **状态完整**：加载（进度环）、空状态（引导文案）、错误（具体可读）、
  悬停、按压反馈、键盘焦点框，一个都不能少；
  注意原生控件（CheckedListBox/TextBox 等）不支持自绘覆盖，
  空状态/圆角这类效果要由外层自绘容器承担
- **动效原则**：克制且有目的——出场用强 ease-out（约 cubic-bezier(0.23,1,0.32,1)
  的手感）、UI 动效 < 300ms（解码动画这类展示型动效除外）、按钮有按压反馈；
  spinner 转速快一点会显得加载更快
- **动画 Timer 的坑**：收敛后自动停止的动画 Timer，在目标值更新时必须重启，否则拖动类交互看起来"卡住"
- 耗时操作必须在后台线程执行，界面不卡死；每个功能页提供运行日志区

## 工程要求

- **零依赖安装**：只使用 Windows 自带组件（.NET Framework 4.x 的 csc.exe、PowerShell、net/cmdkey/netapi32/WMI），不安装任何第三方工具或 NuGet 包；注意自带 csc 仅支持 C# 5 语法（无字符串插值等新特性）
- **模块化**：相同功能只保留一份实现。至少应沉淀：
  
  - 密码算法（独立源文件）
  - 网络操作封装（cmdkey / net use / NetShareEnum / WMI）
  - 探测流程（存凭据 → 清连接 → 枚举验证 → 失败回滚）与映射流程（分配盘符 → 逐个映射 → 汇报），各功能页共用
  - 共享列表控件（勾选 + 盘符徽章 + 拖动排序 + 空状态 + 滚动），各功能页共用
  - 程序集信息（AssemblyInfo.cs：产品名/版本/版权），纳入编译
- **过程文件**：开发过程中持续记录开发日志（环境检查、设计决策、踩坑与修复、测试记录）
- **验证**：每次改动后重新编译并实际验证（启动程序、截图检查界面、关键逻辑的连通性测试），不要只编译不验证；
  截图自动化脚本注意：多显示器下先把窗口移到主屏，DPI 缩放时截图进程须先声明 DPI 感知，否则坐标与像素对不上；
  自动化输入文字时用 SendInput + KEYEVENTF_UNICODE 注入，SendKeys 会被中文输入法（如微软拼音）拦截
- **交付结构**（GitHub 风格，不要求上传）：
